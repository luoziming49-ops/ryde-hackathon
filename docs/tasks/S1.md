## PART B — the organiser's official ticket format

File: sample_data/official/DISP-002.json. Its shape is dispute_ticket / rider_profile / driver_profile / trip_data / gps_telemetry / chat_logs / app_events / cancellation_policy.

There is NO arrival-distance field: arrival comes from app_events (event_type "driver_arrived") or gps_telemetry status "arrived"/"waiting". The no-show rule is a wait timer whose thresholds are carried per ticket in cancellation_policy (free_wait_time_min, no_show_threshold_min). Today our code would mark this ticket insufficient_evidence because closest_distance_to_pickup_m is missing. The organiser's expected answer: cancellation fee UPHELD (our action "no_action").

Add backend/adapters/official_ticket.py: detect the official shape by a top-level "dispute_ticket" key and normalise it into our internal dispute dict. Mapping:

- dispute_type via a dict ({"no_show_charge": "no_show"}); an unknown type escalates with a clear reason, never crashes.
- driver_arrived from app_events, else from telemetry status.
- wait = cancellation_time - (driver_wait_start or driver_arrival_time), in minutes.
- late = max(0, arrival - scheduled), in minutes.
- contact attempts = chat_logs from that sender with type "message" or "call" (system never counts); also a separate driver_call_attempts.
- cancellation_fee from trip_data.
- cancellation_policy thresholds override the global defaults for that one case only (do not mutate the global config).
- rider/driver fraud_flags + fraud_flag_details become fraud flags.
- dispute_history objects {total_disputes, upheld|upheld_against, rejected}: when total >= 3 and rejected/total >= 0.5, add a "high rate of rejected disputes" flag.
- Keep app_events in the response as raw_app_events.

Document the mapping table in backend/adapters/README.md.

API: POST /api/resolve accepts the official JSON directly. GET /api/disputes also lists sample_data/official/*.json, tagged "source":"official".

Tests:

- field-by-field adapter test on DISP-002 (arrived True, wait ~8.0, late 0, contact attempts 5, call attempts 1);
- end-to-end test posting the raw JSON -> action no_action, not escalated;
- missing cancellation_policy falls back to defaults;
- missing app_events still derives arrival from telemetry;
- unknown dispute_type -> 200 + escalated.
