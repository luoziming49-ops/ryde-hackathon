## 用户决定与边界

2026-10-08用户明确要求“先确定mvp模拟测试，最后接入API”。按有效决定DEC-010，先完成无需凭据、无需外部网络的MVP，再接入真实模型及其他外部服务。这里的API后置指外部接入；本机FastAPI接口继续作为模拟测试的实际后端。后续仍由协调助手实施，不交回WorkBuddy，不因缺密钥停止本地开发，也不提前进行收费调用。

保持两类争议、Rider Advocate／Driver Advocate／Judge、确定性规则与金额、现有技术栈。模拟材料与模拟服务显著标注，模拟返回必须经过实际代理、校验、裁决及页面流程。正常案和故障案共用同一条产品路径，不能为演示单独拼接裁决或只覆盖页面元数据。

必要输入仅为本包、[结构建议](../ideas/2026-10-07-structure.md)中WB03/WB04段落和[WB02报告](../reports/WB02.md)。开始每批实现前读取相关实际文件，细化接口与测试；不默认重读历史。

## 执行顺序与验收门槛

### 1. WB03：补齐离线产品流程

可写范围：backend/contracts.py、backend/core/{events,tools,llm}.py及按需新增的本地模拟provider；backend/agents/{base,orchestrator}.py、backend/main.py；frontend/index.html及按职责提取的app.js/styles.css；对应测试与WB03任务/报告。具体新增文件和接口在WB03开工时根据当前代码确定，保持/api/resolve兼容。

- [x] 本地模拟provider可明确选择固定场景；不需要密钥且不会发送外部请求。即使环境存在凭据，显式模拟模式也不能连接真实服务。页面与结果能区分模拟provider、no_key回退和真实模型；现有llm/fallback字段兼容，不靠绿色总徽章判断。
- [x] 三代理依次经过实际后端流程，覆盖全部模拟成功、单代理拒绝后回退、首次无效后重试成功、网络失败四种场景。各代理次数、错误和最终结果一致；仅格式/引用不合格最多修复一次，网络错误直接回退。
- [x] 每次运行有独立run_id和有序事件；记录实际发生的本案工具读取及阶段结果。用受控延迟验证首条事件在最终裁决前到达，延迟只用于测试，不在产品中伪造过程。结束后播放继续标“运行回放”。
- [x] 主张和裁决的证据/政策引用可打开匹配的原文、来源与版本。旧版本或跨案引用拒绝；不得显示上一轮残留数据。
- [x] 出错、重复运行、切换案件的界面状态明确；重新执行不混淆run_id、证据版本或三代理结果。

### 2. WB04：冻结评测并验收模拟MVP

可写范围：tests/、sample_data/evaluation/、对应评测运行入口及文档报告；修复只限验收发现的缺陷。评测预期独立保存并说明依据，禁止从当前实现输出自动反填预期。

- [x] 四案基线保持：0001 partial_refund / 7.87；0002 full_refund / 5.00；0003与DISP-002 no_action / 0.00。覆盖两类争议，不改政策迎合演示。
- [x] 异常矩阵覆盖关键证据缺失、双方证据冲突、缺政策或不适用政策、非法输入、模型格式错误、引用错误、超时/网络错误。缺证不得伪造0元成功结果，非法输入明确拒绝，无法自动判定时按既有业务边界升级或明确失败。
- [x] 浏览器走完整模拟provider→三代理→Guard→页面链路，逐项留输入、独立预期、实际结果与可复现证据。不能用UI元数据替换截图代替该项。
- [x] 回归测试通过；金额、动作、引用、未知值和逐代理状态无未解决关键缺陷；至少一轮完整浏览器演示通过，控制台无未解释错误。
