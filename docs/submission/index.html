What the prototype actually supports.

  • Reported accounts. Agreement, conflict and unconfirmed consent are distinguished. Matching oral accounts remain reported evidence, not independently verified facts. The original route case remains unresolved; synthetic variants are labelled separately.
  • Preset cases and a structured API. The /api/resolve endpoint accepts structured requests. There is no upload or new-case entry screen and no persistent new-case storage.
  • A schematic route plot. Coordinates illustrate input data. Deviation percentages use supplied mileage; routes and traffic fields are not independently checked by a mapping service.
  • A manual-review flag. Unresolved decisive facts leave the amount undetermined. There is no support-team dispatch, case handoff integration or payment execution.

Review the evidence.

  • Historical simulation report: earlier cases and fallbacks; the old 0001 refund is not the current consent-rule expectation.
  • Historical Live API report: actual earlier DeepSeek requests and usage; it does not validate the latest consent logic or new synthetic variants.
  • Current consent scope: rule changes and their verification boundaries.
  • Versioned role prompts: supplied evidence and explicit role boundaries.
  • Run the prototype: setup and operating instructions.

Complete before submitting.

  • Run the WorkBuddy tasks and retain at least three genuine conversation screenshots. Evidence remains pending.
  • Use the verified source-code URL recorded in form copy.
  • Fill personal and team details in the official form; confirm its upload limits and save the submission receipt.
  • Video and public deployment remain optional and are not supplied in this kit.
