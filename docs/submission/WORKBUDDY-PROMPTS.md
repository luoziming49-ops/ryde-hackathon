# WorkBuddy：3个真实辅助任务

目的：用 WorkBuddy 完成范围小、能核查、确有产出的辅助工作。三个任务都不需要提供 API 密钥、调用本项目的外部模型 API 或开发核心代码。每个任务单独开一段对话，一次给足所列附件，要求只输出一次结果；若发现真实问题，再针对该问题追问。

这份提示词不是使用证明。完成真实对话后再截图、核对输出、记录采用或未采用的结果。不要伪造聊天、时间、代码改动或让工具自称项目主开发；不以补齐截图数量为理由虚构贡献。辅助审核范围应如实披露，是否满足赛事资格由主办方判定。

## 任务1 · 审核提交文案准确性

**附加文件：** `docs/submission/FORM-COPY.md`、`docs/reports/WB02-LIVE.md`、`docs/reports/WB03-WB04.md`。仅附这三个已审阅文档，不上传整个仓库或`.env`。

复制以下提示词：

```text
请对附件中的 Ryde Dispute AI 提交文案做一次准确性审核。你只承担辅助审核，不是核心系统开发者。不要联网，不要运行程序，不要读取附件以外的文件，不要索取密钥。

只把两个验收报告作为已有证据，报告日期较新的 WB02-LIVE.md 对真实 API 状态具有优先性；旧报告中的“尚未接入”是历史状态。检查 FORM-COPY.md 是否有以下问题：把模拟当真实模型、把 fallback 算作模型成功、把小样本结果当真实业务准确率、把未部署/未录视频/未提交写成完成、把引用匹配当外部事实真实、把规则分数当校准置信度、夸大工具或商业贡献。

请输出：
1. 最多5项需要修改的表述，每项给出原句、附件依据（文件名及段落）、建议替换句；没有问题就明确写“未发现”，不要凑数。
2. 一个可保存为 SUBMISSION-CLAIM-CHECK.md 的简短检查记录，分“可由附件支持”“仍需人工确认”两栏。
3. 英文短介绍按空格分词的词数。

不要编造实测，不要声称已把建议写回项目，不要为项目作合规认证。总输出控制在700中文字以内，必要的英文替换句不计入。
```

**真实产物：** 审核表和一份简短检查记录。负责人逐项核对后才应用建议；即使无修改，也保留“审核后未改”的真实结果。

## 任务2 · 生成双案演示核对表

**附加文件：** `docs/submission/DEMO.md`、`docs/submission/FORM-COPY.md`。不需要源码或其他历史文件。

```text
请根据附件为 Ryde Dispute AI 制作一页现场演示核对表。你只协助整理演示，不开发或运行核心系统。不要联网、调用模型 API、读取其他文件或执行命令。

请输出可保存为 DEMO-CHECKLIST.md 的 Markdown 文档，最多12个可勾选项目，覆盖：
- 默认 Simulation 标签可见；不得把本地模拟耗时说成真实模型速度。
- 绕路案 RYDE-2026-0001 为 partial_refund / SGD 7.87。
- 未到场案 RYDE-2026-0002 为 full_refund / SGD 5.00；0003 为 no_action / SGD 0.00。
- 打开一条证据引用和一条政策引用，并用 Escape 关闭。
- 错误引用重试后回退、无效 JSON 一次修复、provider 故障回退均如实说明是模拟故障注入。
- 展示逐代理状态及审计导出入口；仅在下载真的完成后勾选“已保存”。
- 说明样例数据/演示政策、未执行支付、规则分数未校准。
- 现场故障时的简短恢复步骤。

每项给出“操作、预期观察、实际结果（留空）”。请保持总流程约6分钟，直接沿用脚本时间分配；可指出时间安排风险，但不要增加现场真实 API 调用，不要写任何项目已经通过彩排的声明。最后列出最多3个讲述中最容易夸大的说法及准确替换说法。总文档不超过900中文字。
```

**真实产物：** 一页可用的 `DEMO-CHECKLIST.md` 文稿。可以保存到本地私有材料目录后逐项彩排；只有实际操作后才填结果，不能预先打勾。

## 任务3 · 审核截图可读性

**附加内容：** 本轮实际应用的桌面工作台截图1张、窄屏截图1张；若裁决或引用没有出现在画面内，可补1张真实裁决/引用截图。先确保截图没有密钥、个人联系方式、私人聊天或其他敏感内容。不要拿设计稿代替运行画面。

```text
请只依据我附的 Ryde Dispute AI 实际界面截图，做一次简短可读性审核。你承担辅助视觉审核，不开发核心系统，也不替我操作浏览器。不要联网或要求任何密钥。

重点查看：案件选择、Simulation / Live API 标识、主动作、裁决与金额、逐代理状态、失败/回退提示、证据/政策引用入口、正文大小和窄屏排版。

输出一张最多6行的表：截图/具体位置、看到的问题、影响、最小修改建议。按“影响讲解或辨认”优先排序。只能陈述截图可见事实；对无法从静态图确认的键盘操作、下载、屏幕阅读器、真实模型调用和对比度数值，明确标注“截图无法验证”。不要编造点击测试或宣称无障碍标准已通过。没有明显问题就如实说，不为凑数建议改动。

最后给出一段不超过100中文字的截图使用建议，说明哪张适合放在项目介绍中、理由是什么。整体输出不超过600中文字。
```

**真实产物：** 截图审核表。建议是否应用由负责人结合真实页面决定；截图无法证明的行为留给实际验收。
